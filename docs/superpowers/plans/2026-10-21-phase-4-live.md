# Phase 4 — Live Companion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While League runs on the Mac, the Live tab on the phone shows the player's own live stats and their lane opponent's, updated every few seconds, with correct waiting / live / stale / ended states. Pulled forward ahead of Phase 3 at the owner's request (2026-10-21).

**Architecture:** The Electron main process polls the LCU gameflow phase (2 s) and, while `InProgress`, the Live Client Data API (2 s). A pure `buildLiveSnapshot` turns the raw payload into `LiveSnapshotV2` (own + lane opponent, nullable fields). A publisher in main broadcasts it on Supabase Realtime channel `user:${userId}` as event `live-snapshot` when it changes, with a 10 s heartbeat and `isFinal: true` once when the game ends. The phone subscribes to the same channel, validates every payload, and renders the mockup-08 layout. No tactical advice; opponent fields are limited to what the in-game scoreboard already shows.

**Tech Stack:** Electron main (Node https to 127.0.0.1:2999), `@supabase/supabase-js` Realtime broadcast, Expo + TanStack-free state (a small hook), Vitest.

**Spec:** `docs/superpowers/specs/2026-10-21-lol-personal-performance-v2-design.md` sections 3 (Riot policy, platform), 5 (LCU mínimo, sin interoperabilidad), 6.2–6.3 (channel + `LiveSnapshotV2`), 8.4–8.6, 9 row 4, 10 exclusions (no "Focus right now", no enemy gold/damage/rank, no objectives).

## Global Constraints

- Payload = `LiveSnapshotV2` from spec 6.3 extended with `isFinal`, `queueId`, `items` per player and `teamKills` (for KP). Every numeric field nullable; `null`, never fake zero.
- Opponent = single enemy with the same non-empty `position`; otherwise `null`. Opponent fields: championName, level, kills/deaths/assists, cs, csPerMin, wardScore, items. Never gold, damage, rank, spells.
- No tactical text. The only coaching on the Live screen is the pre-game goal (Phase 5) — shown as "No goal set" placeholder for now.
- Channel name `user:${user.id}`, event `live-snapshot`. Payload ≤ 4 KB. No tokens, emails or the full roster in the payload.
- Desktop publishes only while signed in; publishing stops on sign-out. Poll cadences: phase 2 s, live 2 s; publish when the snapshot changed or 10 s elapsed (heartbeat).
- Mobile marks the feed stale after 15 s without a snapshot and ended on `isFinal`.
- macOS only. TLS to the Live Client stays unverified (loopback), as ruled in Phase 1.
- `pnpm -r typecheck`, `pnpm -r lint`, `pnpm -r test` green at the end of every task; commit per task with the Claude attribution line.

## Review Focus

1. Two enemies with the same `position` or `position: ''` (ARAM): opponent must be `null`, UI shows own stats only. Test in Task 1.
2. A payload that is not a `LiveSnapshotV2` (older RiftLens client on the same account, or a corrupted message): `parseLiveSnapshot` returns `null` and the screen ignores it. Test in Task 1.
3. Phase bouncing `InProgress → Reconnect → InProgress` (client crash mid-game): the poller must not emit `isFinal` on `Reconnect`; only `WaitingForStats` / `PreEndOfGame` / `EndOfGame` / `None` end a game. Test in Task 2.
4. Game time 0–59 s: `csPerMin` is `null` and the UI shows "—". Test in Task 1.
5. Phone backgrounded then foregrounded after a minute: the last snapshot is older than 15 s → "Reconnecting…" badge until the next heartbeat lands, then live again; the publisher's 10 s heartbeat guarantees this without new game data. Tests in Task 1 (`liveViewState`) and Task 3 (`shouldPublish`).

### Task 1: Live snapshot model, builder, validator and view-state in `@lpp/shared`

**Files:**
- Create: `packages/shared/src/live.ts`
- Test: `packages/shared/tests/live.test.ts`
- Modify: `packages/shared/src/index.ts`

**Interfaces:**
- Produces:
  - `type LivePlayerV2 = { championName: string; position: Role | null; level: number | null; kills: number | null; deaths: number | null; assists: number | null; cs: number | null; csPerMin: number | null; wardScore: number | null; items: number[] }`
  - `type LiveSnapshotV2 = { v: 2; ts: number; isFinal: boolean; gameTimeSeconds: number | null; gameMode: string | null; queueId: number | null; teamKills: number | null; me: LivePlayerV2; opponent: LivePlayerV2 | null; focus: { metric: 'csPerMin'; target: number } | null }`
  - `type RawAllGameData` (subset: `activePlayer.riotIdGameName/riotIdTagLine/summonerName/level`, `allPlayers[]` with `riotIdGameName, riotIdTagLine, summonerName, championName, team, position, level, scores{kills,deaths,assists,creepScore,wardScore}, items[{itemID}]`, `gameData{gameTime, gameMode}`).
  - `buildLiveSnapshot(raw: RawAllGameData, identity: { gameName: string; tagLine: string }, extra: { ts: number; queueId: number | null; isFinal: boolean; focus: LiveSnapshotV2['focus'] }): LiveSnapshotV2 | null` — `null` when the active player cannot be found in `allPlayers` (match by riotId case-insensitive, fallback summonerName). `me.items` = itemIDs > 0 (max 7). `csPerMin` = round1(cs / (gameTime/60)) when gameTime ≥ 60 else null. `teamKills` = sum of kills on my team.
  - `parseLiveSnapshot(payload: unknown): LiveSnapshotV2 | null` — structural validation (`v === 2`, numbers or null, strings, arrays of numbers); anything else → `null`.
  - `liveViewState(snapshot: LiveSnapshotV2 | null, nowMs: number, staleAfterMs = 15_000): 'waiting' | 'live' | 'stale' | 'ended'`.
  - `shouldPublish(prev: LiveSnapshotV2 | null, next: LiveSnapshotV2, heartbeatMs = 10_000): boolean` — true when `prev` is null, when any field except `ts` differs, when `next.isFinal`, or when `next.ts - prev.ts >= heartbeatMs`.
  - `LIVE_OPPONENT_COMPARE = true` (build flag).

- [ ] **Step 1:** Write `tests/live.test.ts` with a raw fixture builder (`raw({ me, enemies, allies, gameTime })`): builder maps own + opponent, items filtered, teamKills summed, csPerMin at 1694 s and `null` at 30 s (Review Focus 4); two enemies same position → `opponent === null` (RF 1); `position: ''` → role null and no opponent; unknown active player → `null`. Validator: round-trips a built snapshot; rejects `{}`, `{ v: 1 }`, a RiftLens-shaped `{ players: [] }`, `me.kills: '3'` (RF 2). `liveViewState`: null → waiting; fresh → live; 16 s old → stale; `isFinal` → ended regardless of age (RF 5). `shouldPublish`: identical except ts within 10 s → false; 10 s later → true; changed cs → true; final → true.

- Create: `apps/desktop/electron/live/live-publisher.ts`

- Test: `apps/desktop/tests/live-publisher.test.ts`

**Interfaces:**
- Produces:
  - `createLivePublisher(client: SupabaseClient, userId: string, deps?: { now }): { publish(snapshot: LiveSnapshotV2): Promise<void>; stop(): Promise<void> }` — lazily subscribes to `client.channel(`user:${userId}`)`, calls `channel.send({ type: 'broadcast', event: 'live-snapshot', payload })` only when `shouldPublish(prev, next)`; on `'timed out' | 'error'` from `send` it drops the channel so the next publish resubscribes; `stop()` unsubscribes.
  - main: when auth is `signed-in` and the detector is `CONNECTED`, start the live poller with `identity = () => summoner riot id`; on every `LiveState` change send IPC `lpp:live-changed` and publish `live` and `ended` snapshots; stop the poller and publisher on sign-out or League closed.
  - `IPC.GetLive = 'lpp:get-live'`, `IPC.LiveChanged = 'lpp:live-changed'`; preload `window.lpp.getLive()`, `onLiveChanged(cb)`.
  - `liveLabel(state: LiveState): string` → idle "Not in a game", waiting "Waiting for a match (ChampSelect)", live "In game as {champion} · {mm:ss}", ended "Match ended".
  - `StatusView` shows a second row with `liveLabel`.
